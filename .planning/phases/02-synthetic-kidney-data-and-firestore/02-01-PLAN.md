<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| doctor client → FastAPI | Untrusted bearer tokens and query limits cross into protected patient routing. |
| FastAPI → repository | Authorized requests cross into server-only patient data access. |
| repository → Firebase Admin Firestore | Privileged backend code accesses Cloud Firestore using backend credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-2-01 | Spoofing / Elevation of Privilege | `GET /patients` | high | mitigate | Declare the unchanged `Depends(require_doctor)` on the handler and test 401, 403, 200, plus repository non-invocation before authorization. |
| T-2-02 | Information Disclosure | Patient list serialization | medium | mitigate | Return typed root summaries only, bound the query to 100, and prevent Firestore snapshots or event histories from crossing the API seam. |
| T-2-SC | Tampering | npm/pip/cargo installs | high | mitigate | Install no package in this phase plan; retain the package-legitimacy gate if execution discovers an actual install requirement. |
</threat_model>

## Planner assumptions

- **FIRE-01:** A lazy Admin SDK client boundary is sufficient for the real runtime and preserves offline importability; accepted by the fake query test here and the approved-runtime check in 02-04 Task 2.
- **FIRE-05:** FastAPI dependency enforcement is the only patient entry point; accepted by explicit 401/403/200 tests and proof that denied requests never invoke the repository.
