# Phase 2 Plan 02: Deterministic synthetic cohort and idempotent Firestore seed

## Phase Goal

**As an** authorized doctor, **I want to** access synthetic CKD histories and a separately modeled simulated IoT stream stored in Firestore, **so that** I can review the two evidence sources without conflating them.

<objective>
Populate the proven read architecture with a reproducible adult CKD cohort and an independently modeled IoT stream through a safe, explicit Firestore seed command.

Purpose: Deliver synthetic-only longitudinal data whose identity, provenance, source separation, and persisted paths remain stable for later phases and evaluation.
Output: Pure cohort models/generator, deterministic owned-path batch writer, backend seed CLI, and offline contract tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Seed CLI input → generator | Operator-supplied seed/version/time/count enters deterministic data generation. |
| Generated cohort → repository | Synthetic records cross into owned-path and size validation. |
| Repository → Firestore | Privileged batch writes mutate persistent Cloud Firestore state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-2-03 | Tampering | Seed manifest and Firestore writer | high | mitigate | Validate synthetic provenance and exact parent/ID path patterns before committing; expose only deterministic `set()` writes and no delete/reset branch. |
| T-2-04 | Information Disclosure | Synthetic generator | high | mitigate | Generate all values from a local PRNG and declared constants, read no patient files/services, and assert explicit synthetic provenance on every persisted record. |
| T-2-05 | Denial of Service | Firestore batch writer | medium | mitigate | Bound cohort size, list size, writes per batch, estimated batch bytes, and document bytes before privileged calls. |
| T-2-SC | Tampering | npm/pip/cargo installs | high | mitigate | Use only already-installed Python and Firebase Admin dependencies; install nothing and stop for package-legitimacy review if that changes. |
</threat_model>

## Planner assumptions

- **DATA-01:** Deterministic generated histories satisfy Phase 2 without any external clinical dataset; accepted by equality, adult/CKD, plausibility, and provenance tests.
- **DATA-02:** Separate typed generation and paths preserve IoT independence; accepted across type, manifest, and fake-client assertions.
- **DATA-03:** Firestore becomes authoritative for every data type actually produced in Phase 2, while rule/prediction values remain absent until their own phase; accepted by Firestore-only repository tests and a no-SQLite source boundary.
- **FIRE-01:** Fake-client conformance plus the later approved-runtime checkpoint is sufficient because local cygrpc import is policy-blocked.
