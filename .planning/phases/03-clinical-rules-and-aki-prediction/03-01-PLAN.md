## Phase Goal

**As a** doctor, **I want to** receive auditable current-rule results and valid 24-hour AKI predictions as separate clinical concepts, **so that** I can distinguish observed clinical status from future risk.

<objective>
Prove the production backend path with one doctor-authorized request that calculates a current creatinine-only rule, emits an explicit unavailable forecast through a stable prediction-engine seam, and atomically persists both as separate result documents.

Purpose: Establish the end-to-end authorization, clinical separation, failure semantics, and Firestore atomicity before expanding model behavior.
Output: Distinct rule/prediction contracts, an injectable orchestration service, protected POST route, deterministic result paths, and offline integration tests.
</objective>

Contracts this plan creates for later plans:
- ClinicalRuleResult is a rule-specific Pydantic model; it is not a forecast base class.
- AkiPredictionResult is a status-discriminated union. Available defines probability and attributions; unavailable defines non-empty reasons and no probability/attributions.
- ClinicalResultEnvelope has separate clinical_rule and prediction fields.
- PredictionService.generate(patient_id, prediction_cutoff) is the single orchestration entry point and accepts an injected prediction engine.
